## Post

Every telephony team has an onboarding process. Most of it lives in one engineer's head. 🧠

So we wrote ours down as an ordered runbook — empty Linux host to smoke-tested phone system, ten steps, no guessing:

🖥️ Public IPv4 host, Docker, DNS for the FQDN — every missing prerequisite blocks a later step, so they are collected first
🔒 Traefik + Let's Encrypt as the single TLS edge; staging CA stays on until the stack comes up clean
🔑 Tokens are **generated by Odoo**, then read out and pasted into the containers — operators never invent a parallel secret
🧱 Firewall service, then trunk gateway, DIDs, outgoing routes and caller IDs — all configured in Odoo, not in a config file
✅ Eight smoke tests, then a handover record so the next operator doesn't start from zero

The point isn't the ten steps. It's that the order is fixed and the secrets have exactly one source of truth.

What's the step your runbook keeps forgetting? 👇
